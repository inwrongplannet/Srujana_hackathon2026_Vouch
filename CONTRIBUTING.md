# Contributing

The team process must not depend on Claude (only Reehan has Claude Code). This is the plain-English version of the rules the skills automate, so anyone can follow it by hand.

## Team and scope
| Person | Role |
|---|---|
| Abhishek | Sets up the repo, plans tasks, reviews and merges |
| Reehan | Builds with Claude Code |
| Abhijit | Feature development |

Nobody owns a folder. Any teammate can change any file through a task, a branch and a PR. Your scope is the task's Files touched in `docs/TASKS.md`; if another in-progress task lists the same file, talk to its assignee first. `.github/CODEOWNERS` requests Abhishek's review on every PR.

## Branching
- Never push to `main`. Branch from an up-to-date `main`.
- Names (kebab-case, 2-4 words): `feat/<name>`, `fix/<name>`, `docs/<name>`, `spike/<name>`. Adding the task id helps: `feat/task-012-portfolio-chart`.

## Commits
- Format: `<type>(<zone>): <imperative summary>`, e.g. `fix(backend): round EMI at the last step`.
- Types: `feat`, `fix`, `docs`, `chore`, `refactor`, `test`. Zones: `backend`, `frontend`, `spikes`, `docs`, `ci`.
- Small and frequent. No secrets, no `.env`, no large data files, no debug code.

## Pull requests
1. Run `make check` locally and fix failures.
2. Push your branch and open a PR. Fill every part of the PR template: what and why (link the `TASK-NNN`), zone, checklist.
3. CI (`make check`) must be green. Abhishek reviews and merges. Do not merge your own PR.
4. Merge conflicts: rebase on `origin/main`. Main's version of a contested line wins and you re-apply your change on top; shared docs keep both sides. For a real logic disagreement, ask Abhishek.

## API contract
Endpoint shapes are written in `docs/API_CONTRACT.md` before they are implemented (Abhishek approves changes). Frontend builds against it; if an implementation must differ, change the contract in the same PR and tell the consumer. Money fields are decimal strings plus a currency code.

## Documentation (mandatory)
Docs ship with the code: any change, even one line, updates the docs it affects in the same PR. The map of "what changed -> which doc" is in `AGENTS.md` (Documentation rules). If there is nothing to document, add `Docs-Impact: none (<specific reason>)` to a commit message or the PR description. When a command, convention or structure changes, update `AGENTS.md` too (`Agents-Impact: none (<reason>)` waives it). Follow `docs/STYLE.md` for terms, headings, file names and README sections. Run `make hooks` once per clone: the pre-push hook runs the same docs gates as CI (`make docs`).

## Money and finance logic
- Never use floats for money. Use `Decimal` (Python) or integer minor units / a decimal library (JS/TS), with an ISO 4217 currency code next to every amount.
- Round only when displaying. Use the formulas in `.claude/skills/finance-domain/SKILL.md` and add a unit test with a known answer for each calculation.

## AI features
If a feature calls an LLM: compute numbers in code and let the model only explain them, ground the prompt in the data, never give advice, and keep a canned fallback for the demo path. Details: `.claude/skills/llm-guardrails/SKILL.md`.

## Secrets and data
- Real keys live only in your local `.env` (never committed). Add new key names to `.env.example`. Share values via a password manager.
- Demo data is fake and generated by `make seed`. No real personal data anywhere.

## Dependencies
Adding a dependency means adding a `docs/DECISIONS.md` entry in the same PR (what, why, alternatives, licence, whether it needs network or a key at demo time).

## Single-writer files
These drift when everyone edits them, so each has one sanctioned way. Claude users run the command; everyone else edits by hand following the same rules.
- **`README.md`** (`/readme`): edit only between `<!-- BEGIN:x -->` and `<!-- END:x -->` markers; never touch the markers or anything outside them. The features table is generated: run `make readme`. `make check` fails if markers are broken or outside text changes.
- **`docs/TASKS.md`** (`/task`): add tasks under Backlog using `docs/templates/task.md` with the next free `TASK-NNN`. Move a task's block between Backlog / In progress / Done without rewriting it.
- **`docs/DECISIONS.md`** (`/decide`): add one dated entry at the top of the list (below `<!-- ENTRIES -->`): Decision, Why, Alternatives, Consequences. Do not edit old entries.

## Features and spikes
- One manifest per feature in `docs/frontend-features/<name>.md` (copy `docs/templates/feature-manifest.md`). Update its status in the same PR as the feature. Then run `make readme`.
- A spike lives in `spikes/<name>/` with a README from `docs/templates/spike-readme.md`. Time-box it, write the findings, and anything useful is promoted through a task.

## Scaffolding backend/ or frontend/
Give each zone its own `Makefile` with `dev`, `test` and `lint` targets; the root `make` delegates to them. Checklist: `.claude/skills/scaffold-zone/SKILL.md`.

## Using other AI agents (Codex, Cursor, Copilot, Gemini, ...)
Any agent is welcome, under the same rules. `AGENTS.md` is the instruction file all of them read (`CLAUDE.md`, `GEMINI.md` and `.github/copilot-instructions.md` just point to it). Claude's skills and commands are plain markdown in `.claude/`, so point a non-Claude agent at the matching file (see the Skills and commands table in `AGENTS.md`). Edit shared rules only in `AGENTS.md`. **OpenCode with free models:** it reads `AGENTS.md`, the skills in `.claude/skills/`, and our wrappers in `.opencode/commands/` and `.opencode/agents/`; `opencode.json` blocks reading `.env*`. Free models may log prompts, so never paste secrets or real data, and give them small, exact tasks (the `Agent:` field in `docs/templates/task.md`). Whatever agent wrote the code, `make check` and the PR checklist still apply.

## Commands
`make dev | test | lint | check | seed | types | readme`. `check` is what CI runs.
